Airdrop 1.6.1 adds a connection-provider picker and fixes premature internet connection verification failures.

- Choose Airdrop (the default, account-free Cloudflare connection), embedded Tailscale, or the same Wi-Fi during first setup. Switch providers from Settings without reinstalling or restarting the app. The last connected provider is remembered for automatic reconnect.
- Wait for the Cloudflare tunnel to register before checking its sharing address. Allow time for DNS/HTTPS provisioning, and use Electron's system-aware network transport for the public verification in the desktop app. A QR code still appears only after an authenticated health check succeeds.
- Keep provider selection usable during a failed or pending connection. Explain download, tunnel connectivity and verification failures separately, with retry and alternative-provider choices.
- Run optional Tailscale as a private userspace node inside the app, with an isolated in-app sign-in window. No host VPN daemon, privileged routes or host execution is installed. Tailscale requires an account with MagicDNS/HTTPS certificates and a phone joined to the same tailnet; it is not the account-free default.
- Preserve the connection/background wizard and editable background/automatic-reconnect preferences.

Free Airdrop internet sharing uses Cloudflare's temporary Quick Tunnel service, including TLS termination and its availability limits. Wi-Fi sharing uses unencrypted HTTP on a trusted network. Mobile access uses Safari/Chrome; physical phone and native Safari testing are not implied by browser emulation.

Flatpak uses the protected signed update channel. After publication, use Settings → Check for updates → Update and reopen the app. Older installations can use `flatpak update io.github.fluffydisk.airdrop-linux`.
