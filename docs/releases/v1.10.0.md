# Airdrop 1.10.0 development notes

The desktop **Nearby Share** tab starts a separate Quick Share session for
**Receive** or **Send**. Receive shows the name advertised by the helper and its
reported Bluetooth status. A registered advertisement is local evidence and
phone-side discovery requires separate observation. Incoming requests show the
sender, file summary and comparison code in the native consent dialog. Accepted
files use the existing `Received` inbox and private staging.

Send opens the system file chooser before starting discovery. It lists current
Quick Share routes from the helper and keeps selected files after a failed send
for a fresh attempt. Compare the code and confirm on the receiving device.
A sent payload with no receiver confirmation is shown as unconfirmed.
Stopping or leaving the tab ends the session and interrupts its active work.
Only the lab can still start its special receiver automatically. The existing
Linux-to-Linux Nearby and guest/link flows remain in Transfer.

## Quick Share prerequisites

From a development checkout, run `npm run prepare-desktop` and build the helper
with `node scripts/build-quickshare.js` (LAN) or
`node scripts/build-quickshare.js --ble-native` (LAN and experimental native BLE).
Launch Electron with `AIRDROP_EXPERIMENTAL_QUICK_SHARE=1`, and also set
`AIRDROP_QUICKSHARE_BLE_NATIVE=1` for the BLE-enabled build. Scoped sessions
require the helper from this source version. Receive skips recipient discovery.
Send skips receiver advertisements and refuses incoming requests.
The existing BLE session logic pauses the application's own scans when it
uses an active Bluetooth transport. Controller limits and other clients'
Bluetooth connections are managed by the operating system.

## Apple AirDrop

The tab reports AirDrop as unavailable. Apple AirDrop requires an AWDL link and
a separate discovery, authentication and transfer provider. The
[OWL requirements](https://github.com/seemoo-lab/owl#requirements) include a
compatible Wi-Fi radio with active monitor mode and frame injection.
[OpenDrop's documented limitations](https://github.com/seemoo-lab/opendrop#limitations)
include automatic receive acceptance and incomplete peer authentication. It
cannot serve as the receive backend for this UI without additional work on
authentication, explicit consent and safe file publication. The cloud instance
has neither an AWDL-capable Wi-Fi interface nor an attached Apple device.
