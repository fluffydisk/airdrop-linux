Airdrop 1.6.7 automatically completes connection setup through a verified phone when desktop DNS cannot resolve the sharing address. Background sharing defaults on.

- A registered tunnel and a healthy local workspace can automatically show a pending QR after desktop DNS checks fail. Scan it with iPhone or Android; the wizard advances after the authenticated client retrieves a valid workspace health response. Pairing alone never marks sharing ready.
- The desktop uses its normal Electron HTTPS transport. Connection setup no longer runs native TLS or certificate-store checks in the desktop process. System DNS and certificate settings stay unchanged.
- Background sharing defaults on for new and previously undecided installations. Flatpak still requires OS permission. Existing explicit off choices are preserved, and the wizard and Settings can change the preference. Closing the window keeps a granted background connection alive; Quit stops sharing.
- Same-Wi-Fi discovery accepts non-public carrier-grade NAT interface addresses while excluding the host Tailscale interface. Local HTTP sharing still requires a trusted network.
- Release publication waits for source-matched Flatpak validation before creating the native tag, verifies and completes partial draft uploads without replacing existing assets, and requests one combined protected publication.

Free internet sharing uses Cloudflare’s temporary service. Tailscale remains an optional embedded provider. Physical iPhone/Android acceptance is not implied by browser-emulation or same-worker gateway tests.

After signed Flatpak publication, use Settings → Check for updates → Update → Quit to finish update, then reopen Airdrop. Allow background permission when prompted.
