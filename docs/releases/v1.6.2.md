Airdrop 1.6.2 lets a paired phone verify internet sharing when the computer cannot reach its own public hostname.

- After a tunnel connects but the desktop HTTPS check fails, choose **Verify with your phone**. The verification code is explicitly pending; pairing alone does not mark the app connected. A real authenticated phone request must reach the local workspace and receive a valid health response before setup continues to the background-sharing question.
- Once verified from a phone, a blocked desktop self-check no longer repeatedly drops a working sharing link. Loss of the tunnel's registered connections still clears readiness and shows reconnecting.
- Distinguish local workspace failures from public DNS, certificate, timeout, connection-refusal and HTTP errors. **Connection details → Copy connection details** copies a report inside the app without pairing tokens, login links, access keys, public sharing URLs or filesystem paths.
- Accept both numeric and string IPv4 family values during LAN discovery. Explain when Wi-Fi sharing cannot find a supported private IPv4 address instead of assuming Wi-Fi is disconnected.
- Keep Airdrop as the default, with embedded Tailscale and same-Wi-Fi alternatives and saved background/automatic-reconnect preferences.

The phone verification path uses the same HTTPS address, gateway token, strict origin validation and secure session cookie. It does not disable TLS checks or declare readiness from a generated address alone. If both networks cannot reach the free service, another provider is still needed.

Flatpak updates use the protected signed channel. After publication, use Settings → Check for updates → Update, quit and reopen. An older package can use `flatpak update io.github.fluffydisk.airdrop-linux`.
