# Airdrop 1.8.0

Open Airdrop on two Linux computers, pair once, then choose a nearby device and send files directly to its receive inbox.

- Transfer opens immediately without a network-provider setup dialog. **Connect a phone by QR** opens the existing guided provider flow when needed.
- Automatic mDNS/DNS-SD discovery with encrypted identity checks, duplicate-name handling, multiple IPv4 interface candidates and reconnect after a changed address or listening port. No IP/port entry for normal use.
- Persistent device pairing with a matching code, friendly names, online/offline checks, quick selection and Forget. Pairing grants file-transfer requests only; it does not grant workspace, filesystem or clipboard access.
- Receiver acceptance by default, with explicit per-device automatic acceptance. Received files appear individually in `Airdrop/Received`, without an unnecessary ZIP.
- Durable 1 MiB chunks, SHA-256 chunk checks, whole-file verification before publication, cancellation, restart-safe retry/resume, and no retransmission of completed files or verified chunks. Changed sources require a new transfer.
- Per-file and overall verified-byte progress, speed, approximate remaining time, verification state and persisted transfer history. Bound simultaneous outgoing transfers to 1–4 (default 2).
- Disk-space preflight and actionable disk-full, declined, offline, timeout and identity-change errors. History is capped at 100 incoming and 100 outgoing transfers; clear history/partial downloads explicitly in device preferences.
- Native and CLI ZIP creation streams through validated file handles instead of buffering every source and the archive in memory. Existing 100 MiB ZIP policy is unchanged. Direct transfers support up to 1,000 regular files and 64 GiB total.

Nearby direct transfer requires Airdrop 1.8+ on both Linux computers and multicast/private IPv4 connectivity. It is independent of the existing workspace internet/Tailscale provider and never silently falls back to another transport. Firewalls must permit mDNS (UDP 5353) and the app's dynamically allocated TCP listener. Disable nearby sharing in Transfer to stop discovery/listening. IPv6-only discovery, folder manifests and direct internet peer transfers are deferred; the existing workspace folder download remains available.

Phones/tablets continue to use camera QR/link guest sharing or the paired workspace in their browser. A browser/PWA cannot perform native mDNS discovery. This release does not implement Apple's proprietary AirDrop protocol or claim interoperability with competitor protocols. Real iOS/Android hardware was not validated in this cloud environment.

Existing workspace files, browser QR pairing behavior, CLI, guest isolation, clipboard, trash, networking providers, signed update verification and package-manager ownership are preserved. New device identities, trust and journals live separately under the desktop profile's `nearby/` directory; older profiles require no migration.
