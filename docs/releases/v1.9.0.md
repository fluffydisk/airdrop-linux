# Airdrop 1.9.0

Choose files, choose a recipient, then Send. The Transfer view queues files until
you send them; uploads from the Files view still go directly to the workspace.

- Share link / QR stays available when no nearby device can be reached. It
  preserves your selection and offers an explicit connection choice when needed.
- New send invitations allow only downloads of the selected files. They do not
  expose workspace files, clipboard access or uploads. Existing guest upload
  sessions remain available separately.
- Invitations wait for connection verification, expire, and stop working when
  revoked or when their connection/session changes. Copy checks the current link.
- Linux discovery supports on-link IPv4/IPv6, scoped link-local IPv6 and unique
  identity-based DNS hostnames. Nearby prefers TCP 53318 and falls back to a free
  port when occupied; advertised ports remain compatible with existing peers.
- Previously paired devices can reconnect through a revalidated saved endpoint
  when multicast is filtered. Existing certificates, pairing permissions,
  resumable chunk journals and file integrity checks are preserved.

Client isolation or separate VLANs can still prevent direct connections. Use an
HTTPS sharing provider permitted by the network, or another permitted connection.
Local HTTP links require direct reachability and are separately disclosed.
This release does not change institutional access restrictions.

Native Android Quick Share and Apple AirDrop are not included. Phones can use
the browser QR/link route without installing a companion application.

Runtime packaging excludes development helper trees and rejects misplaced
experimental binaries, including in source-built Flatpak and AppImage assembly.
Release acceptance exercises extracted AppImage contents and native packages
with Chromium sandboxing on both architectures before publication.

Portable installations use the existing updater or matching architecture's
download. Package-manager installations retain their package manager's update
ownership. Distribution/store availability is reported separately from GitHub
release availability; install only the validated artifacts for your architecture.
